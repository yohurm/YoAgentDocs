# 多范围架构审查：分波次收口

从多次全栈分层审查里抽出的**方法**。不绑定某一仓库。作业步骤以 [architecture-review 手册](../../playbooks/architecture-review.md) 为准。

## 背景

大型桌面或分层仓库往往有十几条所有权边界（运行时、协议、领域、能力 crate、壳、组件库、页面模块）。单次「扫全仓」会漏链路；修完一个包就宣布完成，会把邻层回归漏掉。需要可重复的波次，而不是感觉上的收口。

## 方法

**1. 先切范围，再并行只读**

按所有权与层切开互不重叠的范围（例如运输 / 领域 / 能力 / 壳 / 组件库 / 页面模块）。每个范围一名审查员，只读、不改文件。层名跟类型包，不套另一栈词汇。

**2. 结论只有两种**

- **通过（CLEAN）**：清单全绿，且该范围内无未修的分层问题、无残留技术债务。禁止在文末设「非阻塞观察」或「已知债务」来跳过修复环。
- **未通过（HAS_ISSUES）**：列出 P0 / P1 / P2，每条带文件:行与**正确层**。级别只排动手顺序；列出的项全部修完才可再标 CLEAN。

库缺口（能力库缺控件、缺头槽）记在已通过项，不记消费模块违规——除非消费方自写了第二套。

分阶段时：每一刀只声明一块所有权，但这一刀必须整理到干净再收口。下一刀另开范围，不把债留在本刀的观察列表里。

**3. 修复员按所有权改，审查员不改**

每个实现员只动声明路径。不要回滚他人未提交改动。需要改邻层契约时，只开「一处单源」（例如协议常量、壳错误枚举），并在任务里写死。禁止兼容层与双轨 API。

**4. 同一波次修完，再开下一波全范围复审**

未通过项全部落地后，对**全部**已声明范围再审一遍，且必须重读当前树，不得沿用上一波「通过」。不要因为一个范围变绿就单独再开一轮；也不要缩范围冒充收口。

**5. 收口条件**

Goal / 任务完成：**同一波次**里全部范围都是通过，且无挂账分层债。缺一路、只修不复审、或 CLEAN 报告仍列未修观察，都不算完。迟到的上一波回执，在已经开了更新波次之后，不再重开作业。

**6. 对着持有改动的工作树**

未推送的本地改动，对「只克隆远端提交」的审查员不可见。审查与修复必须在实际持有改动的工作树上做。

**7. 报告固定六段**

覆盖文件；1–3 条设计前链路；清单逐项通过/失败+证据；问题清单（级别 + 文件:行 + 正确层）；已通过项（含对照已声明修复）；结论通过或未通过。只审则不写「实现后新路径」，用现状位置当通路证据。

## 反复出现、应写进清单的漏项

这些是分层原则的操作化，不是某一产品的特例：

| 漏项 | 正确层怎么做 |
|------|----------------|
| 超时、帧头长度、通道容量、泵批次散落在业务分支 | 进该仓已声明的常量池；调用方只引用 |
| 把用户句子或宿主 Display 塞进邻层错误类型 | 错误只分类；载荷是路径/计数/标识；编排层自建枚举，IPC 边界再映射 |
| 预热/准备槽位 Busy 时一律等待 | 先比**请求意图**；意图不符则取消并视为未命中，不等错误准备完成再丢 |
| 回退/重试关掉仍属于该代际的管道或令牌 | 代际资源由槽位所有者关；本次 attempt 用子令牌 |
| 用 sleep / 轮询等槽位 | 只等条件通知 |
| 把不变量失败包装成运输/协议错 | 按不变量写（`if let` / 断言），不伪装成线路故障 |
| 产品回退谓词吞掉运输超时 | 回退只认声明过的失败类，不扩到协议/IO/取消 |
| 同一通道的读排空与写入分属两个「只负责泵」的文件 | 读写同属已声明的控制层文件 |
| 命令层编排、服务层回指命令 | commands 薄转发；服务不引用命令模块 |
| 原生测试链到发行版以外的 `link` | 用该平台工具链的链接器（Windows 用 MSVC），不要让 Git 自带目录抢 PATH |
