# 架构与代码质量

自底向上看：先模块边界和数据流，再具体实现。架构结论在数据链路证据齐之前，不算审查完成。

## 旧架构不打补丁

解决问题时，禁止继续在旧架构上修补、打补丁或做防御性加固。正确顺序：

1. **严格调研优秀设计：** 先读官方规范与已验证的开源实现（见 [design-sources.md](design-sources.md)；实现路径不明则走联网深研）。出处写进结论。没有出处不得发明「应该这样」。
2. **梳理完整数据链路：** 入口 → 状态持有 → 业务变换 → 副作用终点。相关链路一条不漏。节点不清就继续查，禁止用猜测填空。
3. **重设计架构：** 按目标分层改边界、状态归属与契约；一次替换旧路径。
4. **重构问题并清理旧代码：** 把问题落到新通路上解决；删除旧实现、双轨与残留防御。不要注释冻结。

局部逻辑错误且现有分层仍正确时，只在该层做行为修复。只要拟议改动是在旧边界上「先顶住」「先加固」，就必须按上列顺序重设计，不得降级成补丁。

## 分阶段整理到干净

重构、审查、修复都允许按所有权或按数据链路**分阶段**推进。阶段切的是「这一刀必须整理完的范围」，不是「这一刀先凑合、债挂后头」。

每一阶段结束时，该范围内必须是干净架构：

- 目标通路已替换旧通路；旧实现、双轨 API、兼容层、防御性修补已删除。
- 审查清单在该范围内可全部勾选。问题清单（含曾被标成 P2 的项）已闭合；否则结论只能是 HAS_ISSUES，继续修。
- **禁止**把范围内的分层问题降级为「非阻塞观察」「不影响收口」「后续再清」而宣布 CLEAN。
- **禁止**维持半成品：新路径已接上、旧路径仍留作过渡；门面已拆、实现仍堆在 API 文件；只修了紧急项，其余分层债挂在通过报告文末。

优先级只决定本阶段内的动手顺序，不决定能否跳过。同链路暴露的架构问题纳入本阶段，不另开「非阻塞」账户。

下一阶段必须另声明范围与验收，并在那一刀里同样整理到干净。不得在本阶段 CLEAN 报告里用观察列表代替下一阶段任务。范围外、且不在本阶段相关数据链路上的模块，仍不顺手重写——那是下一刀的范围，不是本刀的脚注。

## 严禁残留技术债务

本阶段声明范围内，技术债务**零残留**。发现即纳入本阶段闭合，不得降级、不得挂账、不得用「已知问题」「可后续」「用户可先用」交差。本阶段**新引入**的债务一律禁止。

下列均算残留债务，收口前必须清掉：

| 类别 | 禁止留下的形态 |
|------|----------------|
| 架构债 | 兼容层、双轨 API、旧路径注释冻结、适配器顶住错误边界、防御性修补、越级、门面夹带实现、混职责文件未按层拆开 |
| 实现债 | 本范围引入或触及的 `TODO` / `FIXME` / `HACK` / `XXX`、未实现桩、永远为真的开关、跳过或忽略的测试、用 `any` / 强制转换捂住类型、复制第二套逻辑 |
| 验证债 | 为让门禁变绿而扩「已知差异 / 例外」清单、测了未覆盖本阶段行为、空测试、把失败标 skip |
| 收口债 | 非阻塞观察、后续建议列表、P2 挂账、「先交主路径」 |

只审不改时：范围内存在上表任一项，结论只能是 **HAS_ISSUES**，不得标 CLEAN。改代码的阶段：上表任一项未清，本轮未完成。

既有债务若在范围外且不在本阶段相关链路上：写入**下一阶段任务**（模块、链路、可判定验收），禁止只写一句「仓库里还有债」。既有债务若在本阶段相关链路上：视同本阶段债务，必须清零。

## 高内聚、低耦合

- 一个模块只承担一类职责；能说清「它不做什么」。
- 依赖指向稳定抽象，而不是互相点名内部类。跨模块只走已有的公开边界（API、IPC、领域接口）。
- 发现两处做同一件事：合并到该职责所在层，不要再加第三套。
- **依赖单向：** 只指向邻层或稳定抽象。下层不持有上层引用；结果用返回值、事件或观察回传。需要「反向通知」时先改分层，不要让下层点名上层类型。

## 模型跟随所在层

- 持久化模型、领域模型、传输模型分别定义；在层边界显式转换，不共用同一个结构「图省事」。
- 每个字段能说清来源和调用方。禁止为「将来可能用到」预留字段；禁止同一字段用不同取值表达不同结构。
- **错误只分类。** 变体表达类别；载荷是路径、计数、标识等结构化字段。禁止把用户句子或邻层 `Display` 塞进另一模块的错误类型。编排层（壳、会话）自建枚举，到 IPC / HTTP 边界再映射。

## 禁止散落硬编码

下列内容进入该仓库已有的常量池、token、配置或资源，不在业务分支里写死：

- 颜色、字号、圆角、间距、动效时长
- URL、路径、设备节点、超时、重试次数、魔法数字与协议字面量
- 用户可见文案（跟现有国际化/资源方式走）

真正的单点定义（token 文件、schema 默认值）不算硬编码。复制同一字面量到第二处即违规。

## 严禁兼容层

兼容性代码与兼容层**不得存在**。禁止用兼容类、适配器、包装函数、别名、双轨 API、版本 if、过时目录把错误边界「先顶住」。这是「旧架构不打补丁」的具体形态，不得用兼容层代替重设计。

发现上述任何一种，不得只删包装或再叠一层。必须：

1. **沿全部相关数据链路查根因：** 谁依赖这份兼容、上游契约为何分叉、下游为何吃不下统一模型；相关链路一条不漏。
2. **重设计完整通路：** 在正确层改边界、状态与契约，一次替换旧路径，而不是局部打补丁。
3. **以质量收口：** 设计前/后链路证据齐；任务范围内无双轨、无残留兼容代码。不要注释冻结。

「相关」指该兼容点的全部上下游，不是只改发现它的文件。禁止借机扫全仓库无关模块。

已征得同意的对外契约一次性迁移（过渡代码做完即删）不是本条所说的兼容层；长期双轨与永久适配器仍违规。

## 禁止防御性修补

根因在哪一层就改哪一层。禁止用旁路把现象盖住，也禁止把「加固旧架构」当成修复：

- 对本不应为空的值加空判断：掩盖上游未赋值。追源头保证契约，而不是在消费处吞掉。
- 大范围 try-catch 吞异常：问题被藏住。在产生异常的位置修。
- 延时、重试、标志位规避时序：制造不稳定补丁。修真实时序或状态归属。槽位等待用条件通知，不用 sleep 轮询。
- 回退或重试时拆掉仍属于该代际的管道、根取消令牌：把产品策略做成了误关资源。代际资源由槽位所有者关；单次 attempt 用子令牌。
- 把编程不变量包装成运输/协议错误：掩盖契约。按不变量写，不伪装成线路故障。
- 只改 UI 隐藏错误数据：表象消失、根因仍在。修数据的生产与传递。
- 为「保险」加无依据分支或双轨：扩散复杂度。确认边界后一次替换。产品回退谓词不得扩到未声明的运输失败类。

## 数据链路证据

提出或落地一套分层时，写清这两段，缺一不可：

1. **设计前：** 现状从入口到存储/设备/IPC 的调用链（谁持有状态、谁变换、谁出副作用），以及问题出在哪一跳。
2. **实现后：** 同一条链路上的新路径，用代码位置或运行证据（日志、截图、测试）说明数据怎么走通。

没有链路证据的「感觉更干净」不算架构完成。链路节点不清晰时必须继续查，严禁猜测。

## 文件单一职责

- **一个文件一类职责。** 模型、策略、视图、样式、测试、对外门面分文件（或分类型）。禁止在同一文件里叠测量、手势、绘制、状态机和业务拼装。
- 文件名反映职责（`model` / `policy` / `view` / `api`），不用 `Utils`、`Helper`、`Impl2` 当垃圾桶。
- 发现一个文件同时服务两层：拆开，而不是再加方法「先用着」。

## 对外 API 禁止耦合实现

公开门面（`api/`、包入口、`YoXxx`、IPC 命令薄层）只表达契约：类型、枚举、工厂/转发、稳定事件。

- **禁止**在 API 文件里写几何、Path/绘制、手势、测量、持久化、网络或领域算法。
- **禁止** API 文件 `import` 内部实现包（`internal`、非导出模块、领域私有类）。只允许依赖同层装配入口（如 `XxxImpl`），实现细节留在内部。
- 多种外观用参数/配置，不为每种预设在 `api/` 下复制实现类或补丁目录。

组件库细则见 [ui-kit/file-srp.md](../by-type/ui-kit/file-srp.md) 与 [ui-kit/public-api.md](../by-type/ui-kit/public-api.md)。

## 遵守已声明的分层

- 每个仓库只认一套已声明架构（文档或目录约定）。调用不得越级。
- **层名跟类型包走**，见 [stack-layering.md](stack-layering.md)。Android 有界面的应用模块才使用 View / ViewModel / Model；Windows 桌面（WebView + 本地后端）使用 View → store 投影 → 类型化 IPC → commands → domain；组件库使用 L0–L5。禁止用其中一套去改写另一套。
- 越级的共性：展示层直达数据源或领域内部；门面夹带实现；本该在实现层的填充/判定/校验/编排出现在 UI。具体禁例写在各类型包。
